## ld-stacker-gui
A GUI for [ld-disc-stacker](ld-disc-stacker.md), in the style of ld-analyse: it shows the captures of a disc next to their stack, so that the difference in quality can be seen, and writes the stack.

```
ld-stacker-gui [files...]
```

Give it TBC files or CVBS files (`.cvbs`), or a `.stack` session file saved earlier, or drop them on the window (one or several files at a time). Only what a stack can be made of is taken: a TBC, CVBS or LDX capture (an LDX file with several captures adds each of them), or a session; the chroma file of a Y/C pair goes with its luma, and any other file is left out, with a message in the status bar that names it. The sources must all be TBC or all CVBS (the two are not mixed) and of one video system: PAL and NTSC cannot be stacked together, and a source of the other one is refused.

### Window

- **Sources** (left): one row for each source. The **Info** button beside Add source opens a panel between the list and the picture with what is known of the source that is chosen: where it is and how its metadata is kept, the video (system, frames, size, sample rate, levels, who decoded it), what the VBI says of the disc (CAV or CLV, first and last picture or time, chapters, frames with VBI, where the numbering jumps, repeated numbers, padded frames), whether the metadata say it was mapped, the SNR of its metadata and, for an LDX file, its history (who did what, when and with which arguments). It follows the tab that is shown. The panel is hidden when the program starts; showing it makes the window wider by its room, and hiding it makes the window narrower by the same (unless the window is maximized). A session opens with the stack off, whatever it was when it was saved. Drag a row to reorder the sources; the check box leaves a source out of the stack without removing it; the offset is a number of frames to shift the source by, in addition to the alignment by the numbers of the disc (see Timeline); the SNR button opens a window with the SNR of the source over the whole disc (one window for each source).  Right click, or the Delete key, removes a source. **Follow map** (on by default) makes a source use its mapping (ld-discmap) when there is one: if the metadata of the source do not say it was mapped, the mapping that exists takes its place, in its name and in what is stacked (the file beside it with _map in its name, or the track of an LDX file that is the mapping of it, which has `mappedFrom` in its parameters; see the container format, section 7.4); off, the capture it was made from is used. A session saves the file that is used and the state of the box (`followMap`, written when it is off), so that every tool that reads it uses the mapping, or the capture, in the same way. The row says "mapped" when the metadata say so. The Follow map boxes can be changed with the stack off only, and the stack is off when the program starts.

**Timeline.** The sources are lined up by the numbers of the disc that their VBI gives (the picture of a CAV disc, the time of a CLV one): the source whose first frame is the earliest begins the timeline, and each other source begins where its numbers put it, plus its own offset. The stack goes from the smallest number to the largest of any source that is on; where a source has no frame (before it begins, after it ends, in a gap) its picture is blank, and where no source has a frame the stack is blank. The frame counter and the slider show the whole timeline for the stack only; a source tab shows the duration of that source (frame 1 to its last frame, the frames of its file), and moving between tabs keeps the same moment of the timeline as far as the source reaches it; the label beside the frame counter says where the picture is, on the disc and in the file of the source that is shown. A source whose **Follow map box is off** is used as the capture is, as if its mapping did not exist: its numbers are not used and it begins at the start of the timeline (the number 0 of the disc, plus its offset), while the sources that follow the map stay where their numbers put them, with blank frames between. A source whose VBI gives no number (an unmapped capture whose first frames cannot be read, for instance, when its Follow map box is off) begins at the number 0 of the disc, plus its offset: it is the one at the start of the timeline, and the sources that have numbers stay where these put them. The numbers are read from the first frames of the capture (the one that most of them agree on counts, so a corrupt number does not move a source); a mapped source gives clean numbers. A session saved from here keeps the offsets that were set, and ld-analyse and ld-chroma-decoder line up the sources of a `.stack` by the numbers of the disc as well; ld-disc-stacker lines them up with its first source and the offsets only, so the stack it writes is not the union of the sources.

**Dropouts.** Each source has a **Show dropouts** box in its row (ticked to begin with): the dropouts that the metadata of the capture have are drawn on the picture, in the colour of the source (the one of its row), each field of the frame in its own shade (the first field lighter, the second darker, so the rows can be told apart). On the stack every source whose box is ticked is drawn; on the tab of a source, that source. A frame that the metadata mark as a dropout as a whole (the frames that ld-discmap could not number are written so) is not drawn for that source, since it would colour the whole picture. In the status bar, **Hide capture dropouts** hides all of them whatever the boxes say, and **Show residual dropouts** draws, on the stack, the dropouts that the stacking left (where every source that has the frame has a dropout), in red, the first field lighter than the second. They are drawn on the picture before the view is applied, so the field views and the chroma picture show them too. The boxes are not kept in the session. **The residual dropouts have a colour of the theme**: a default for each theme (light red on a dark theme, a darker red on a light one), which can be changed in **View > Theme > Customize** (*Dropouts left by a stack*), and the stack output window and the picture follow it. The same entry appears in the theme editor of ld-analyse, which does not use it.

**Dropout graph.** **View > Dropout graph**, or the **Dropouts** box beside the SNR boxes (they are the same: ticking one ticks the other, and the choice is kept), shows a graph under the SNR graph: the total length of the dropouts of the metadata of each frame (both fields, in samples), one curve for each source that is on in the colour of its row on the stack, and that source on its tab (from its own first frame, as the SNR graph does). Like the SNR graphs, the scale is fixed and the same for all of them (from 0 to the longest dropouts of any frame of any source), so that sources and tabs can be compared. A frame that is padded or marked as a dropout as a whole is left out. Clicking or dragging on it goes to the frame, as on the SNR graph. On the stack the graph has one more curve, in the colour of the residual dropouts: the length of the dropouts that the stack is left with in each frame. It is measured with the SNR of the stack (the **Measure** of the stack), which then reads whole fields instead of the lines of the test signals, so it takes longer: it is only done when the dropout graph is shown, and the cache keeps it as it does the SNR. The scale goes from 0 to the longest dropouts of any frame of any source, the same for the main graph and the windows of the sources, so that nothing is cut off, and its values over a thousand are written with a k. When neither **White SNR** nor **Black PSNR** is ticked the SNR graph goes away and only its boxes stay, to bring it back. Each source has a **dropout button** in its row, beside the SNR one, that opens its dropouts in a window of its own (on the scale that is the same for every graph of the dropouts, along the timeline, with what the stack is left with when it was measured, in the colour of the residual dropouts). The window bar has the colour of the source. The **Update SNR** button of the Info panel (under the Map section) measures the SNR of the source that is chosen again, from the test signals of every field, and writes it in its metadata (ld-process-vits; it keeps a backup of the metadata file beside it, `.vbup`). For a track of an LDX file the video and metadata are taken out, measured, and the new metadata are added to the file as a block (the previous ones stay in it). The source is read again afterwards, so the SNR graphs show the new values. It is available for TBC captures with the stack off.

**Mapping.** Turning the stack on (the Stack button) when some sources that are on follow the map and have no mapped version asks whether to map them: *Map, keep a copy* writes `name_map.tbc` (with its metadata and audio) beside each capture, *Map, overwrite* replaces the capture and its metadata by their mapping (it cannot be undone, and is asked again), and *Stack without mapping* stacks as they are. The **Map** section of the Info panel (a button with its icon and the name beside it, under the information) does the same for the source that is chosen, whatever its Follow map box says, and does nothing if a mapped version is there already (that one is then used). ld-discmap does the work in the background: a small bar shows in the row of each source being mapped (it turns red, "Map failed", if ld-discmap did not succeed), a window has the log of the tool, and the stack is turned on when it is done. A frame that has no number and cannot be given one does not make ld-discmap fail: it is kept, given a number and marked as a dropout over the whole frame (the stack does not use it); the log says so when it happened. A capture that is overwritten is written under a temporary name first and put in place when it is complete, so that a failure leaves it as it was. Captures are mapped from here as .tbc files or as tracks of an LDX file, not CVBS ones (ld-discmap does not map them from here) or the chroma file or track of a Y/C pair. A track of an LDX file is taken out into a folder beside the file (`name.mapping-tmp`), mapped there by ld-discmap, and put back by `ld-container`: *keep a copy* adds the mapping to the file as a track of its own named "(mapped)" with `mappedFrom` naming the original (`ld-container add --mapped-from`; the file is written again, and every source that reads it is read again afterwards), and *overwrite* removes the track and adds the mapping in its place, with the name it had (under a new track id, which the source then uses). The file is written under a temporary name and put in place when it is complete, so that a failure leaves it as it was. A capture with no `.pcm` beside it is mapped without audio.
- **Stack button and tabs**: one tab for each source, with the SNR of the frame being viewed (the best source in green), and and, in the row of buttons under the picture beside Chroma, the Stack button, which says the SNR of the stack. Stack on: the picture is the stack. Stack off, or a tab clicked: it is the source of that tab. Switching the button compares the stack with the source, at the same zoom and position. The keys 1 to 9 pick a source and 0 (or S) switches the stack.
- **Picture**: the first source imported is shown at 100% and the window is resized to it; those after it change nothing. This is the **View > Resize on first file import** toggle, on to begin with and kept in the settings; off, the first source does not change the zoom or the window. **View > Scale window with zoom** (off to begin with, also kept in the settings) resizes the window to the picture each time the zoom changes (the + and - buttons, the box, the wheel), as the first import does; nothing happens when the window is maximized or full screen. Zoom by typing a value, with the + and - buttons (they go through 100%) or with Ctrl and the wheel, and drag the picture to pan. The Original size button (the last icon of the row, with the zoom ones) goes back to 100% and resizes the window to show the whole picture. The aspect ratio button switches between the display aspect ratio of the video (DAR 4:3 or 16:9, as ld-analyse shows it, the default) and square pixels (SAR 1:1). Line doubling enlarges the picture without smoothing it, which is what shows the difference between sources; Smooth is the other choice (View > Scaling algorithm). The Chroma button decodes the picture to colour; View > Chroma decoder configuration opens the configuration of the decoder (PAL filter, NTSC 1D, 2D or 3D, gain, phase, noise reduction). A 3D decoder looks at the frames either side, so for the stack those are stacked too. View > Enhance changes the brightness, contrast and gamma of what is shown, to bring out the defects, and nothing that is stacked.
- **SNR graph** under the picture: the white SNR (blue) and the black PSNR (orange) of what is shown, over the whole disc, with a marker on the frame; the two check boxes above it switch each curve. The values are in dB: the scale is written on the right of the graph, and the values at the cursor are read in a box that follows it. The graphs of the sources and of the stack share **one vertical scale**, that holds the SNR of all of them (both curves, ticked or not), so that they can be compared from one to the other; **View > Same scale for all the SNR graphs** (on by default) turns it off, and each graph has then the scale that fits what it shows. For a source it is the SNR of its metadata. The graph of a source is its SNR as the metadata has it (at once, a session that was opened too); the **Measure** box beside the White SNR and Black PSNR boxes measures it instead from the test signal lines of the fields of that source, in the background (a percentage shows in the title while it goes), one source at a time: the SNR window of a source has the same box. The stack has no SNR in any metadata: with a single source on it is that source (and the box is for that source), and with two or more it can only be measured, from the stacked test signals. That measure reads the test signals of every field of every source, which is a lot of reading from the disk, so it is made only when the stack is shown (or the SNR window of a source, which has the stack behind its curve): with the stack off, adding sources reads nothing from the video. The **Measure** box of the graph of the stack is on and cannot be changed, since the stack has no metadata to show instead. It begins about a second after the last change (a source added, an offset turned). What was measured is kept for as long as the program runs, and **File > Export session** writes it in the `.stack` file (the SNR and dropouts of the stack, and the SNR measured of the sources, under the keys of the captures, offsets and options that they were measured from; the specification has the format), so that opening the session again, here or in ld-analyse, does not measure again. A measure that is not good for the captures any more (a file of another size, an offset changed, other options) is not used, and is not written again. What was measured is kept for as long as the program runs, by what it depends on (the files with their name and size and, for the stack, the offsets and the stacking options), so it is measured again only when one of them has changed: turning the stack off and on, or going back to an earlier setting, does not read the video again; the same goes for the **Measure** box of a source. Click the graph to go to a frame. The SNR window of a source has the same two curves; a check box adds those of the stack, in grey, to compare. What is measured (the stack of two or more sources, or a source with its box ticked) is shared between several threads: all the processors but one, up to eight, each reading the files with a handle of its own.
- **Frame navigation**: first, previous, next and last frame, the frame number, a slider; the left and right keys step.
- **Frame, split or field**: a list beside the aspect ratio button (key F goes through it) chooses what the picture is: Frame, Split (both fields of the frame, the first above the second), or Field 1 or Field 2 (one field with its lines doubled). The navigation is by frame in all of them, and the choice is kept in the session.
- **Stacking mode**: auto or one of the modes of ld-disc-stacker. In auto the status bar says which one the number of sources gives. Edit > Stacking options sets the rest: the threshold of the smart modes, differential dropout detection, pass-through, the integrity check (used when processing to a file) and the field order.
- **Status bar**: how many sources contribute to the frame, the mode, and what is shown. On the right it says the video system and the format of the sources: for example NTSC TBC or NTSC CVBS.
- **View > Stack output**: a window with the stack, which stays in view while the main window shows a source.
- **View > Tint the source rows**: the list of sources is a list: a line under each row and a bar of the colour of the source on its left, and a faint tint of that colour (a dark transparent one) across the row, stronger for the row picked. The tint can be turned off here, and is kept between sessions. The SNR window of a source has a bar of its colour at the top, and its icon is of that colour, so that the windows can be told apart.
- **View > Theme and Style**: the colour themes and widget styles of ld-analyse (Auto, Light, Dark, Soft light, Dim, Dark grey, and a custom theme to edit with Customize...), kept between sessions. `--force-dark-theme` forces the dark theme for one session.

The stack shown is made with the same code as ld-disc-stacker, for the frame viewed only.

### Menu

- **File > New session** (Ctrl+N) empties the window (the sources are taken out of the list; the files are not touched), and **Open session** and **Export session** load and save a `.stack` file: a JSON file with the sources (file, on or off, offset), the stacking options, the output file and what the window shows. ld-disc-stacker takes it as it is (see its page), so a session made here can be stacked from the command line.
- **File > Process** asks where to save the stack and the metadata format (SQLite or JSON), then stacks the sources that are on. The file can also be an **.ldx** file: the window then asks whether it holds *the sources and the session* (the sources that are .tbc or .cvbs files are brought into the file as tracks, with their metadata and audio, together with the session `.stack` that stacks them: tools read the file as the stack of its sources and nothing is stacked now; the tracks of other LDX files stay links) or *only the stack* (the sources are stacked now: ld-disc-stacker sends an LDX stream to a file, which ld-container writes again with its index). The metadata are in the file, so the format box does not apply, and the box *In an .ldx file* chooses whether the video and the audio are kept not compressed or lossless (FLAC, and FFV1 for CVBS). The video is TBC or CVBS as the extension of the file says (.tbc or .cvbs); when that is not the format of the sources, ld-tbc-to-cvbs or ld-cvbs-to-tbc converts the stack, and ld-sqlite-to-json or ld-json-converter converts the metadata if it is not in the format asked for. The tools are those beside ld-stacker-gui. A stack that does not finish is removed.

The session can be opened in ld-analyse, which shows the stack as the frames are asked for, and decoded by ld-chroma-decoder, without the stack being written first.

### Not yet

Mapping the tracks of an LDX file from the window (the mapped track would be added to the file with `mappedFrom`), and updating the SNR of the metadata.

## Icon

The application icon is a grey disc with the colours of its reflection, an arrow down and the discs that are stacked, in different greys and each a little off the one above. Sources are `Graphics/ld-stacker-gui.svg` (48 pixels and up) and `Graphics/ld-stacker-gui-small.svg`, drawn on the 16-pixel grid so that it stays readable at 16x16 (used for 16, 24 and 32). The PNGs and `appicon.ico` (the icon of the Windows executable) are rendered from them.

## LDX files

An LDX file (see [the container format](../Specifications/container-format.md)) can be added as a source: each TBC capture it holds becomes a source of its own (named after its track, shown as `file.ldx #3`), and an LDX file that keeps a stacking session is added as one source, the stack of that session. **File > Open session** also reads the session an LDX file keeps; saving it goes to a `.stack` file of its own and never over the LDX file. A source that is a track of an LDX file is saved in the session as the file and the id of the track.
